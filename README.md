# RecipeExtractor

> A standalone recipe extraction service: get only ingredients, only instructions, or the full
> recipe from a URL, HTML, or plain text.

**RecipeExtractor is a learning project.** All implementation code is written by hand. AI was used
only for planning, architecture discussions, and code review — not for generating the
implementation.

RecipeExtractor turns a recipe page into a structured `RecipeDocument`. It is consumer-agnostic:
[light-groceries](https://github.com/overkri/light-groceries) is one client, not the owner. The API
can return only the sections you ask for — ingredients, instructions, title, servings, or
everything.

## Why this exists

- Learn Java 25: records, sealed interfaces, pattern matching, virtual threads.
- Learn AWS SDK v2 against LocalStack: S3, SQS, DynamoDB, SNS.
- Practice partial extraction, provenance, retries, DLQ, and caching.
- Build something useful for light-groceries without coupling the extractor to the app.

## What it does

- `POST /v1/extract` with `include: ["ingredients"]`, `["instructions"]`, or `["full"]`.
- Accepts a URL, raw HTML, or plain text.
- Extracts JSON-LD, microdata, and text sections; merges by confidence.
- Reports provenance per section: `json-ld`, `microdata`, `text-section`, `heuristic`.
- Returns partial results instead of failing the whole request.
- Runs batch jobs through SQS with retries and a DLQ.
- Archives raw HTML in S3 for reprocessing.
- Stores job state in DynamoDB.
- Caches results in Caffeine (L1) and Redis (L2).
- Ships a CLI for local debugging.

## Example

```http
POST /v1/extract
{
  "source": { "type": "url", "url": "https://example.com/borscht" },
  "include": ["ingredients"],
  "require": ["ingredients"]
}
```

```json
{
  "source": {
    "type": "url",
    "url": "https://example.com/borscht",
    "finalUrl": "https://example.com/borscht",
    "fetchedAt": "2026-11-11T10:00:00Z"
  },
  "recipe": {
    "title": "Борщ",
    "ingredients": ["1 кг свёклы", "200 г капусты", "2 л бульона"]
  },
  "provenance": { "ingredients": "json-ld" },
  "warnings": []
}
```

## Stack

| Layer | Choice |
|---|---|
| Language | Java 25 (LTS) |
| Web | Spring Boot 4 |
| AWS | AWS SDK v2 + LocalStack (S3, SQS, DynamoDB, SNS) |
| Cache | Caffeine + Redis 8 |
| Parsing | jsoup + Jackson |
| Tests | JUnit 5, Testcontainers (LocalStack, Redis) |
| Build | Gradle 9.9 |

## Architecture

See [architecture.md](./architecture.md) for the full design: modules, domain model, API,
extraction pipeline, LocalStack setup, and the DynamoDB vs PostgreSQL decision.

```text
Consumers (light-groceries, CLI, other apps)
  -> RecipeExtractor API (Java 25)
      -> SQS -> Worker -> S3 (raw HTML)
                       -> DynamoDB (job state)
                       -> Redis + Caffeine (cache)
```
